# AI Diff · 跟写工作台

在 VS Code 中运行现有仓库审查、AI 解释和业务图谱，将基准到结束提交的最终变化合为一个目标，用原生虚影一比一跟写。

## 安装与使用

需要 VS Code 1.100 或更新版本，以及 PATH 中可调用的 Git。首次打开工作区时需要信任该工作区。

通过 VS Code 扩展页面的“从 VSIX 安装”选择 `ai-diff-follow-0.1.24.vsix`。

- 命令面板执行 **AI Diff: 打开审查与学习工作台**，即可使用原有提交图谱、全文 Diff、AI 审查和学习功能。
- 执行 **AI Diff: 创建跟写练习**，选择参考仓库、基准提交、结束提交和一个尚不存在的练习目录。
- 新练习默认把整个范围合为一个目标：从基准版本开始，直接跟写到结束版本，全部文件一致后一次完成。例如 `A → B → C → D`，基准 A、结束 D 就只练习 A 与 D 的最终净变化，不要求依次完成 B、C。
- 基准和结束点都直接从提交列表点击选择，不需要输入 hash。列表显示提交说明、作者、日期和分支/标签，可输入关键词筛选；默认显示所有本地可见引用的最近 100 条提交，点击 **加载更早的 100 条提交** 可继续浏览。手动输入提交 SHA、分支或标签保留在列表末尾作为备用入口。列表与输入框切换窗口后保持打开，按 Esc 取消。
- 扩展会创建独立的本地克隆，并在新窗口中打开练习专用工作区。已有练习执行 **AI Diff: 启用稳定跟写窗口**（侧栏标题的窗口图标）即可切换，原有进度继续使用。
- Explorer 中的 **AI Diff 跟写** 显示“合并跟写”、基准到结束的范围及净变化文件。点击文件直接打开单个真实练习文件，并定位第一处待跟写内容；目标直接在正文中以原生多行虚影显示，你可以照着输入。
- 从普通资源管理器或标签页进入跟写文件、恢复已有任务时，也会自动定位第一处待写内容，避免旧光标停在其他行导致看不到虚影。首次定位不会被布局刷新或过期的异步结果取消；进入后自主滚动、选择和输入不会反复跳回。
- 整段新增的位置在原有代码上方单独显示 **⬇【此处待新增 · N 行】** 提示行（使用原生 CodeLens，需保持 `editor.codeLens` 开启），并用绿色横线及行号旁的“＋”标清插入边界，已有代码不染色。当前待写处可点击 **显示虚影**，后面的新增处仅作顺序提示，前面的改动完成后再启用。提示只说明操作，目标代码仍以原生多行虚影显示；提示不写入文件，也不弹出额外说明浮层。底部状态栏和 **AI Diff: 定位下一处跟写** 仍可定位。
- 行内补写也显示独立说明，例如 **待补写 · 第 23 列「、超级发发发」**；替换明确显示 **「旧内容」→「新内容」**，删除说明要删的片段。同一行的多处变化合并提示数量，当前一处可点击定位，输入后按顺序更新。行内补写只用行号旁加号标记，不画整行新增横线，避免误认为整行需要重写。格式差异会显示空格、Tab 和换行标识，并注明不影响完成判定。
- 全文件需要删除或替换的旧内容会提前用红色背景和删除线标记，整行删除显示 **待删除 · N 行**，局部删除明确为 **仅红色字符**。纯空白差异不标红，保留可忽略的格式提示，继续显示后面未写的正文。多行修改先按词对齐，再细化实际错误字符，不会因为缺少参数或缩进不同而把已写对的整段调用标红；纯删除的方法仍完整标出。即使第一处新增 import 尚未跟写，后面的待删内容也可见；这些标记不弹出说明浮层。删改后标记随未保存文本更新，完成后消失；虚影仍按下一处差异提供，通过定位继续跟写。完成校验忽略空白的规则不变。
- 标记只说明操作，目标代码继续使用原生多行虚影，二者都不会自动写入文件。完成校验仍读取实际保存内容，忽略空白的规则保持不变。
- 在文件末尾空行追加多行时，先显示待写正文，最后一个换行随后继续提示，避免宿主将候选移到上一行后隐藏。此处理不改变目标文本、Tab 或换行格式。
- 在已有行之前新增整行时，新增行完整显示为虚影，下一条已有代码保持正常显示，不会把两行相同的 `import` 前缀拆成灰色片段。文件首行直接显示待写内容，从光标处输入，写完该行再按 Enter；无需预先空出一行，也不会异步把光标移回上一行。文件中间仍可从上一行末尾的换行开始跟写。
- 多行虚影保留目标的真实换行、空行、缩进和 Tab；新增文件打开时可直接看到多行待写代码。输入后自动显示剩余内容。单次最多提供 60 行、4,000 个 UTF-16 单位（含保留的当前行文字），输入后继续提供后面的内容；不把整份大文件一次塞进原生差异渲染器。
- 此次根据用户反馈，明确恢复正文多行虚影作为实现选择，移除代码透镜目标行及用 `↵` 假装换行的文字装饰。含换行的候选范围延伸到当前行末，并原样保留右侧已有代码，避免两个 import 连行或吞掉原代码。替换先删除红字，再显示插入目标。
- 跟写以虚影稳定显示为优先：专用工作区启用内联建议和子词模式，失焦及代码片段填参时保留虚影，并抑制自动补全弹窗抢占。语言索引和补全仍可使用，按 `Ctrl+Space` 手动调出。设置只保存在 `.git/ai-diff-follow.code-workspace`，不修改全局配置或 `.vscode/settings.json`，也不影响目标快照校验；已有专用工作区的用户调整不会被覆盖。项目自身更高优先级的语言或文件夹设置仍可能覆盖工作区配置。
- VS Code 1.138 及更新版本定向请求跟写提供器，并在专用工作区开启宿主的补全冲突共存设置；旧宿主使用通用内联请求。不匹配的手动补全仍可能暂时隐藏目标，按 Esc 关闭菜单可恢复。编辑器完成布局、切换文件和切回窗口时会重新请求；点击状态栏会先恢复编辑焦点再定位。
- 跟写文件中 **Enter 只换行**；没有补全列表时 **Tab 缩进、Shift+Tab 取消缩进**，不会接受整段虚影。普通语言补全列表打开时仍可用 Tab 选择条目；代码片段中的 Tab/Shift+Tab 仍跳转占位符。**Ctrl+Right（macOS 为 Alt+Right）接受下一个虚影词**，可连续按键逐词补全；没有虚影时沿用原有按词移动。Esc 隐藏虚影，退格、删除和撤销保留正常编辑行为。离开练习文件或完成会话后撤销这些按键保护，不修改用户键位文件。
- Enter 会先关闭当前补全候选，再执行原生换行，保留自动缩进和撤销；候选声明“换行即可接受”也不会因此写入整段代码。此规则只作用于跟写文件中的编辑输入，普通补全仍可用 Tab 主动选择。
- 连续换行后立即输入字符时保持原输入顺序。编辑器自动缩进与目标使用的空格或 Tab 不同，也能在已有缩进后继续跟写；待写正文内部的换行、空行和缩进仍按目标显示。只剩格式差异时，状态栏显示“正文已完成 · 格式差异可忽略”。
- 光标离开待写行、选择文本、输错字符或缩进导致需要删除旧内容时，原生虚影仍可能隐藏。待删内容会标红，删改后继续显示。底部 **跟写 · 第 N 行** 或 **AI Diff: 定位下一处跟写** 可定位。菜单中显式执行接受内联建议仍是主动接受操作；正常跟写无需使用该操作。
- 新增文件的实际内容起初为空；只有输入或接受建议才修改文档。状态栏“目标就绪”只说明已生成候选，不作为宿主实际显示的证明。读取失败会明确报错并支持重试；极长的当前行无法提供候选时也会显示原因。第三方扩展组合仍需在实际环境确认。
- 需要查看完整差异时，可右键文件选择 **查看目标对照**。默认虚影方式是本次产品交互约定，实际文本仍保留原有代码，不会自动清空待改文件。
- 点击侧栏 **保存并检查内容** 查看遗漏；全部一致后点击 **校验并完成练习**。仅保存练习目录内已打开的文档；其他工作区草稿保持原样。
- 按用户要求，目标中已删除的历史文件在列表中默认打勾，显示 **目标已删除 · 默认完成**，无需手动删除，也不阻塞整个练习完成。扩展保留练习目录中的旧文件，点击该项查看删除前的只读历史，不再提示清空。二进制资源可右键同步，覆盖前确认；文本代码需要手动跟写。
- 关闭后重新打开同一练习目录，自动恢复进度。进度存放于练习仓库的 `.git/ai-diff-follow.json`，不会创建练习提交。
- 已有逐提交练习继续按原进度恢复。如需合并，执行 **AI Diff: 将当前练习合并为一个目标**，保留原始基准、最终目标和所有文件编辑；仅转换进度记录，不保存或清空未保存草稿。旧练习原有“校验并进入下一步”仅在逐提交模式下显示。
- 逐提交转合并后，仍认可已完成步骤中的删除文件，不要求删除保留的草稿。已完成的练习再次改动后，侧栏显示“已完成 · 内容有改动”；再次完成会重新校验，检查本身不改写历史完成记录。
- **AI Diff: 搜索工作区代码符号** 使用当前语言扩展提供的工作区符号查询。

代码补全、定义跳转、引用和诊断由当前 VS Code 语言扩展提供。练习目录是实际工作区，仍需准备对应的项目依赖、SDK、Python 环境或 C/C++ 编译数据库。只读历史文档不保证跨文件语言服务。

## 一致性与第一版边界

- 按用户确定的产品方式，新建练习默认合并整个提交范围，只校验基准和结束两份快照；中间改了又还原的代码、临时新增后删除的文件不要求跟写。
- 合并范围直接比较两端内容，基准和结束可以位于不同分支，无需祖先关系；包括 squash/rebase 前原提交仍可在本地解析的情况。两端不能选同一个提交。这里的“合并”是合并跟写目标，不会执行 Git merge、squash 或改写仓库历史。
- 为兼容已有记录，旧逐提交练习仍沿父子关系继续原路线；只有这一模式要求祖先关系。未标注模式的旧记录按逐提交解释，主动转换后按合并目标保存。
- 开始时固定完整提交 SHA，并在练习仓库中保留结束目标引用，参考分支移动不会改变跟写目标。
- 校验整个目标快照，覆盖本步遗漏、其他受版本管理文件的误改和未忽略的额外文件。Git 忽略的生成物不计入额外文件。
- 按用户要求，完成判定忽略文本内全部空白（空格、Tab、换行及 Unicode 空白），包括字符串和注释中的空白，只比较剩余字符，不做语义等价判断。虚影仍显示目标原有的空格、缩进和换行，显示与差异定位规则不变；仅格式不同也能保存并检查通过，无须逐一修改空白。
- 校验先比较 Git 内容哈希，遵循项目的 `.gitattributes`、换行和 clean filter 规则；哈希不一致时按现有预览支持的 UTF-8/GB18030 编码解码文本后忽略空白。二进制或无法解码的内容仍要求哈希一致。目标仍存在但缺失的文件、历史之外的额外文件仍须处理，不要求提交哈希相同，不检查 Unix 可执行位。
- 删除项默认完成只适用于基准或已走过步骤中存在、当前目标已不存在的路径，兼容旧逐提交练习中此前已删除但保留的文件。重命名的旧路径默认完成，新路径仍须跟写；任意额外文件不会因为不在目标中就自动通过。保留的旧文件仍在实际工作区，可能继续被语言服务或构建工具读取；默认完成不代表工作区精确复现目标快照。
- 第一版不支持子模块、符号链接、虚拟工作区、浏览器版 VS Code，也不支持移动练习目录后自动修复路径。
- 参考文本沿用现有预览限制：5 MiB、100,000 行。超过预览限制的文本文件需要外部工具处理；编码保存由 VS Code 当前文档编码负责。
- 二进制资源同步按实际字节判类型，不受文本预览大小上限限制；仍需明确确认，文本代码不能借此自动填入。同步会将整个资源读入内存。
- 目标将旧文件改成同名目录时，保留的旧文件可能阻挡新子文件创建。须由用户先把冲突旧文件移到练习目录外备份，再打开新文件；扩展不会自动删除旧文件。
- 0.1.23 起逐提交转合并会保留已完成步骤的历史；已被旧版本转换并丢弃的历史不能可靠自动还原。
- AI 分析仍需要自行配置模型服务。API 配置使用 VS Code SecretStorage，其他页面状态使用扩展本地存储。AI 对话继续沿用原项目的本地持久化逻辑。
- 本扩展提供受限消息通道；页面不能任意执行 VS Code 命令。本地后端由扩展管理独立进程，使用随机端口和仅宿主持有的访问令牌，关闭页面会取消其请求，扩展退出会停止后端。AI SDK 的全局异常和退出监听不会进入共享扩展宿主。

## 本地开发

从仓库根目录执行：

```powershell
npm.cmd ci
npm.cmd ci --prefix vscode
npm.cmd run build:vscode
```

使用仓库内 `.vscode/launch.json` 的 **AI Diff · VS Code 扩展** 启动配置按 F5。在扩展开发窗口中运行上述命令。

打包：

```powershell
cd vscode
npx @vscode/vsce package --no-dependencies --skip-license
```

运行时业务依赖已经分别打入 `out/extension.cjs` 和 `out/backend.cjs`；安装插件后不需要单独启动 npm、Vite、Express 或 Electron。已有浏览器和 Electron 启动方式保持可用。

自动化测试覆盖真实 Git 练习目录、路线验证、全量内容校验、进度恢复、路径边界、页面消息流、取消、设置隔离及模拟 VS Code API 下的原生命令衔接。模拟宿主测试不能替代实际 VS Code 内的语言扩展、补全和界面验收。
